## Scorecard Customization

The key differentiator: scorecard reads user-defined layers from config, not hardcoded Kapi layers.

`kapi-sprints.config.md` (generated by `/sprint init` or `/sprint spec`):

```markdown
# Project: MyApp

## Layers (what /scorecard audits)
1. API — routes, validation, error handling
2. Auth — session, permissions, tokens
3. UI — components, accessibility, responsiveness
4. Data — models, migrations, queries
5. Tests — coverage, e2e, integration

## Conventions
- TypeScript strict mode
- Tailwind for styling
- Vitest for unit tests

## Sprint Directory
docs/operations/sprints

## Blackboard Directory
docs/operations/blackboard
```

Every project gets a custom audit model. Scorecard skill reads this instead of hardcoded layers.

## Agents (2)

### Auto-Invocable Agents

| Agent | Trigger | What it does |
|-------|---------|-------------|
| `arch-reviewer` | Activated by `/dev` when architecture decisions surface | Reviews architectural patterns, suggests ADRs |
| `test-planner` | Activated by `/dev` when new functionality is built | Plans test coverage, suggests test structure |

These are auto-invocable — Claude Code activates them based on context, not explicit user command.

**Generalization:** Remove Kapi-specific architectural patterns. Keep the meta-patterns (review triggers, ADR suggestions, test planning heuristics).

## Commands

### `/sprint` (Primary)

```
/sprint init          → Scaffold project structure + config
/sprint spec          → Backwards build: conversational PRD generation
/sprint dashboard     → Hint to run npx kapi-sprints dashboard
/sprint status        → Quick text summary of current sprint
```

### Subcommands via Skills

```
/preflight <version>  → Run pre-sprint check
/prd <version>        → Generate sprint plan
/dev <version>        → Enter dev mode
/test <version>       → Run test validation
/scorecard <version>  → Audit against quality layers
/walkthrough <version>→ Code review
/checkpoint           → Save session state
/resume               → Restore from checkpoint
/post                 → Post to blackboard
```

## Hooks

`hooks/hooks.json`:

```json
{
  "hooks": [
    {
      "event": "session_start",
      "command": "echo '\\n💡 Dashboard: npx kapi-sprints dashboard (in another terminal)\\n'"
    }
  ]
}
```

Minimal — just a helpful hint on session start. No auto-launching processes.
